# Уведомления пользователю во время прогона

## CONSTRAINTS

- Канал – тот, что задают глобальные правила пользователя или `AGENTS.md` (например `lan-notify` или HTTP-шлюз из `~/.claude/CLAUDE.md`). Канала нет или он недоступен – работай без уведомлений, одна строка об этом в отчёте; обходов не ищи.
- Вызов `/pipeline` разрешает уведомления этого прогона, если правила пользователя это допускают.
- Не отправляй секреты, содержимое приватных файлов, данные работодателя. Текст – задача, фаза, что нужно.
- Ошибка отправки – одна строка в чат, без повторов в цикле.

## ROUTING

| Событие | Что отправить | Звук |
|---|---|---|
| старт прогона | живая карточка прогресса: задача, фаза, шаг n из m; id → `state.notify.progress_id` | без звука |
| смена фазы | правка той же карточки (не чаще раза в 2 с) | без звука |
| остановка (`blocked`) | вопрос с вариантами, до 4 по ≤32 символа, рекомендация первой; id → `state.notify.ask_id` | со звуком |
| `done` | короткая итоговая карточка: PR/ветка, гейты, `not_run` | со звуком |
| обрыв на ошибке API | отправляет хук `StopFailure` (`references/hooks.md`) | со звуком |

### Вопрос и ожидание ответа

1. Отправь вопрос, сохрани id в state, в чат – тот же вопрос одной строкой.
2. Ожидание – **фоновой** командой (`run_in_background`), ход заканчивается. Пример для `lan-notify`:

```sh
mid=$(lan-notify -s agent-pipeline --ask "<вопрос>" --options "<рекоменд.>|<вариант 2>" --context "<задача, фаза>")
lan-notify --wait "$mid" --timeout 1800   # фоном; код 3 = нет ответа за 30 мин
```

3. Пришёл ответ (из фона или в чате) – очисти `blocked` и `ask_id`, продолжай фазу.
4. Нет ответа – не повторяй вопрос; независимую работу продолжай, остальное ждёт пользователя в чате.

В песочнице Claude Code HTTP-шлюз в локальной сети требует `--noproxy ''` и разрешения хоста в `allowed_domains` – по правилам пользователя.
