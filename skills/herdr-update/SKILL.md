# Herdr update review

Сверяет патч-ноуты Herdr с кастомом пользователя: где новая версия покрывает кастом – ставит штатное, клоны модов сливает с новой версией, новые функции рекомендует под то, как пользователь работает.

`{SKILL_DIR}` = папка этого SKILL.md. `{HOME}` = `$HERDR_APP_HOME` или `~/.config/herdr-app`.
Скрипты: `{SKILL_DIR}/scripts/herdr_review.py` (читает; пишет только `mark`) и `{SKILL_DIR}/scripts/herdr-forks` (слияние клонов).

Главное правило: где новая версия покрывает кастом пользователя, берём штатное и убираем кастом полностью, без своих надстроек. Кастом остаётся только там, где штатного нет, и у каждого оставшегося куска есть причина одной строкой. Данные пользователя (сводка использования, его файлы) остаются на машине: в отчёт – выводы, не содержимое.

## Scope

In: обновление Herdr desktop (herdr-app) – клоны штатных модов и раскладок, свои моды, `keys.json`, `settings.json`, рекомендации новых функций.
Out: консольный herdr (herdrdev/herdr), установка самого обновления (её делает Herdr), написание новых модов.
Fallback: нет клонов и своего `keys.json` – только шаги 1–4 и рекомендации.

## Preconditions

- [ ] `herdr-app --version` печатает версию.
- [ ] `herdr-app status` отвечает JSON: окно Herdr открыто (нужно для `usage` и проверки).
- [ ] `python3 --version`, `git --version` (слияние клонов), `node --version` (проверка слитого JS).
- [ ] Сеть до `github.com`, `raw.githubusercontent.com`, `api.github.com`.
- [ ] Песочница агента пропускает `herdr-app`, сеть GitHub и запись в `~/.config`, `~/.cache`, `~/.local/state`; иначе каждую такую команду – отдельным вызовом вне песочницы.

Не прошёл пункт – стоп (`BLOCKED`), назови пункт.

## Алгоритм

```
- [ ] 1. Версии: прошлый разбор и установленная
- [ ] 2. Патч-ноуты диапазона
- [ ] 3. Инвентарь кастома и сводка использования
- [ ] 4. Разбор пунктов по корзинам
- [ ] 5. План пользователю – STOP до «да»
- [ ] 6. Клоны: слияние и замена кастома штатным
- [ ] 7. Keys и settings
- [ ] 8. Проверка в окне
- [ ] 9. Перенос и заметки пользователя
- [ ] 10. Отчёт и mark
```

### 1. Версии

`python3 -I {SKILL_DIR}/scripts/herdr_review.py since`.
- `reviewed` – версия прошлого разбора из файла состояния `${XDG_STATE_HOME:-~/.local/state}/herdr-update/reviewed`. Нет файла – самая старая база клонов с пометкой `(from clones)`. `unknown` – спроси пользователя, с какой версии смотреть.
- `installed unknown` – стоп, спроси пользователя.
- `reviewed` равна `installed` – разбирать нечего: одна строка, `DONE`.

### 2. Патч-ноуты

`python3 -I {SKILL_DIR}/scripts/herdr_review.py changelog <reviewed> <installed>`. Читай целиком. Любое утверждение о версии или функции – только из этого вывода.

### 3. Инвентарь и использование

`python3 -I {SKILL_DIR}/scripts/herdr_review.py usage` – клоны, свои моды и раскладки, копии `*-edited`, раскладка и моды в ней, отличается ли `keys.json` от штатного, заданные ключи `settings.json`, что открыто: spaces, удалённые машины, вкладки, программы, sub-agents.

Для каждого клона – что в нём своё: `python3 {SKILL_DIR}/scripts/herdr-forks diff <клон>`. Свои моды без `cloned_from` читай целиком. Копии `*-edited` сравни со штатными файлами.

Пользователь ведёт заметки о своей настройке (README конфигов, заметки, память агента) и ты знаешь где – прочитай: там причины кастома.

### 4. Разбор

Каждый пункт патч-ноутов – в одну корзину:

| Корзина | Что делать |
| --- | --- |
| Покрывает кастом | Шаг 6: штатное вместо своего, своё удалить |
| Меняет то, чем пользователь пользуется | Применить: слияние клона, ключ, настройка |
| Новая функция под его работу | Рекомендация: что даёт, на каком его сценарии, цена. Без согласия не включать. Исключение – `restored default` в `keys` (шаг 7) |
| Не про него | Пропустить, в отчёте только счётчик |

«Под его работу» – только с опорой на факт из шага 3: агенты, которые он запускает; удалённые машины; число spaces и вкладок; worktree; его моды и клавиши. Без опоры – «не про него». Ищи то, что убирает ручной шаг или кастом: штатная клавиша вместо своей, настройка вместо мода, API мода, который упрощает свой мод.

### 5. План – STOP

Покажи план: корзины, какие файлы изменятся, что станет штатным, рекомендации. Жди «да». Ответ «только часть» – делай только её.

### 6. Клоны

1. `python3 {SKILL_DIR}/scripts/herdr-forks update -n` – что сольётся чисто, где конфликт. Клоны `-n` не трогает, но пишет файлы конфликтов и кэш баз.
2. Конфликт разреши по главному правилу. Файл конфликта – путь из строки `CONFLICT`. Штатный код бери как есть, своё оставляй отдельными функциями рядом, чтобы следующие слияния не цеплялись. Проверка: `node --check --input-type=module < файл`.
3. Бэкап клонов в `~/.cache/herdr-forks/backup/manual-<время>/`, разрешённые файлы – в клоны, затем `python3 {SKILL_DIR}/scripts/herdr-forks update`. Клон, который скрипт всё ещё зовёт конфликтом (в нём уже разрешённая версия): `cloned_from.version = <installed>` в `mod.json` вручную и вручную слей изменения штатного `mod.json` старой базы и новой версии.
   Клон раскладки, который скрипт велит обновить руками: `herdr-forks diff <клон>` покажет своё; перенеси изменения штатной раскладки в клон, выставь `cloned_from.version = <installed>`.
4. Клон, в котором не осталось своего, – предложи удалить и вернуть штатный мод в раскладку.
5. `python3 {SKILL_DIR}/scripts/herdr-forks status` – всё `current`.

### 7. Keys и settings

`python3 -I {SKILL_DIR}/scripts/herdr_review.py keys <reviewed> <installed>` – штатные привязки диапазона, которых нет в его `keys.json`, и привязки, которые штатный файл убрал или сменил, а у него остались. Строка: `[restored default]` или `[new action]`, затем состояние.
- `restored default` и `free` – действие было штатным и раньше: добавь в тот же контекст (`global`, `terminal`), что в штатном файле.
- `new action` – новая функция: только рекомендация.
- `dropped` / `changed upstream` – предложи убрать или обновить.
- `action already on …` – у него своя клавиша на это действие: не трогать.
- `key taken by ours` – конфликт клавиш: рекомендация.

Новые ключи `settings.json` – рекомендации, кроме корзины «меняет то, чем пользователь пользуется».

### 8. Проверка

- `herdr-app check {HOME}/mods/<мод>` для каждого изменённого мода.
- `herdr-app status` → `errors`: новых нет (недоступная удалённая машина к обновлению не относится).
- `herdr-app shot <временная папка>/herdr.png` и посмотри снимок: вкладки, sidebar, список агентов на месте.

### 9. Перенос и заметки

- Пользователь синхронизирует конфиги между машинами (dotfiles, общая папка, свой скрипт) – перенеси изменённые моды, раскладки, `keys.json`, `settings.json` по его процессу. Служебное (`.claude/`, `*.d.ts`, `jsconfig.json`) не переносится.
- Есть заметки о настройке Herdr – допиши, что стало штатным, что осталось своим и почему.

### 10. Отчёт и mark

Отчёт по формату из «Пример». Когда пользователь принял результат: `python3 -I {SKILL_DIR}/scripts/herdr_review.py mark <installed>`. Затем строка «что улучшить в скилле», если по ходу что-то мешало.

## Типовые сбои

| Сбой | Действие |
| --- | --- |
| Скрипт пишет `cannot get …` (сеть, 404) | Стоп, `BLOCKED`: назови URL |
| `usage` пишет `window not reachable` | Попроси открыть окно Herdr, повтори |
| `CONFLICT` в `update -n` | Шаг 6.2, файл из строки `CONFLICT` |
| `node --check` не прошёл | Чини разрешение конфликта, в клон не клади |
| `herdr-app check` упал после записи | Верни клон из бэкапа, `DONE_WITH_CONCERNS` с ошибкой |

## Hard Stop Rules

- `installed unknown` или не пройден Preconditions – стоп.
- До «да» на шаге 5 ничего не пишется в клоны, `keys.json`, `settings.json`.
- Ничего не удалять: клоны, свои моды, привязки – только предложить.
- Функции из корзины «новая функция» без согласия не включать.
- Перед записью в клоны – бэкап.

## Definition of Done

- `herdr-forks status` – всё `current`.
- `herdr-app check` проходит для каждого изменённого мода; в `herdr-app status` → `errors` нет новых.
- Отчёт по корзинам показан, пользователь ответил на рекомендации.
- `mark <installed>` выполнен.
- Статус: `DONE`, `DONE_WITH_CONCERNS` (что не так) или `BLOCKED` (чего не хватает).

## Пример

Вход: «обновился Herdr, проверь» (прошлый разбор 0.1.15, установлена 0.1.16, три клона, свой `keys.json`).

Результат:

```
Herdr 0.1.15 → 0.1.16 – DONE

Заменено штатным
- tabs-title: свой показ заголовка агента на вкладке → штатный label() (#737)

Применено
- клоны agents-title, spaces-wt, tabs-title, раскладка – слиты, check passed
- keys: cmd-a terminal.select_all [restored default] – в terminal

- tabs-title: переименование вкладки – тосты берут имя вкладки, штатно не меняется

- worktrees.directory: папка новых worktree – у вас 5 репозиториев с worktree

Пропущено: 31 пункт не про вас

```

## Команды проверки

```bash
python3 {SKILL_DIR}/scripts/herdr-forks status
herdr-app check {HOME}/mods/<мод>
herdr-app status
python3 -I {SKILL_DIR}/scripts/herdr_review.py since
```

## Gotchas

- Свой `keys.json` целиком отключает штатные привязки: новые штатные клавиши сами не появятся.
- `herdr-forks update -n` не трогает клоны, но пишет кэш баз и файлы конфликтов в `~/.cache/herdr-forks/`.
- Копии `*-edited` (Herdr делает их при правке штатных файлов) – не клоны: у них нет `cloned_from`, сравнивай со штатными.
- Тело тоста собирает ядро из имени вкладки, а не из того, что мод показывает на вкладке.
- Песочница агента часто режет сокет `herdr-app` и запись в `~/.cache`: ошибка `Operation not permitted` – это песочница.
