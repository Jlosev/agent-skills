# Когда звать local-llm

Звать скрипт только если **все три**:

1. Пачка однотипного (десятки кусков) или один длинный сырой текст под шаблон. Не одна фраза.
2. Ответ – JSON-схема или короткий шаблон. Без инструментов, без MCP.
3. Цена ошибки низкая: черновик, тег, выжимка. Не mutate задач, не outbound-чат, не `action_me`.

Иначе оркестратор делает сам. Нет формулировки «кажется выгодно».

| Да | Нет |
| --- | --- |
| теги / класс / шум-не-шум на пачке | judgment-heavy classify другого пайплайна |
| саммари транскрипта в черновик | outbound-чат / DM |
| выжимка по фиксированным полям | Task-субагент, любой MCP |
| эмбеддер уже loaded – это не этот скилл | одно короткое суждение |

Fallback: `--health` ≠ 0 или complete exit 2/3/4 → сделать самому. Exit 4 – один retry только на parse. Третий identical вызов запрещён.

## Health ladder (batch)

1. `lms server status` или `local_complete.py --health`
2. При сомнении – `/api/v0/models`, смотреть `state` → `loaded`
3. Один health на всю пачку, не на каждый элемент

## Batch-паттерн

Оркестратор – Shell-цикл по файлам в `.tmp/local-llm/` (промпт + схема + `--out` на элемент). Не `Task`, не REST без `json_schema`.
